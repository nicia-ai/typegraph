**`paginate()` and `stream()` advance when a full node or edge is selected and the order names a system field.** A query such as `.select((c) => c.u).orderBy("u", "meta.createdAt", "desc")` built its continuation cursor from the selected node, which carries `createdAt` as `meta.createdAt`, so the cursor held no value for it. `stream()` then yielded the first batch forever, and `paginate({ after })` returned the first page again. The same applied to `meta.validFrom`, `meta.validTo`, `meta.updatedAt` and `meta.deletedAt`, and to an edge alias's `fromId` and `toId`, in both directions. Before this release's `orderBy` field-name change these fields were spelled `"created_at"`, `"valid_from"`, `"valid_to"`, `"updated_at"`, `"deleted_at"`, `"from_id"` and `"to_id"`. Projection selects such as `(c) => ({ id: c.u.id })`, and ordering by `id`, `kind` or a property, were not affected. The cursor now reads each system field where a selected node or edge holds it, through the same lookup a projection select uses.
