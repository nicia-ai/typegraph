`importGraph` and `importGraphStream` with `onConflict: "update"` now refuse a composition move of an `existence: "required"` part whose two rows do not abut. A document could end the part's attachment at one instant and attach it again from a later one, or attach it with no `validFrom` (so the new window opens when the import writes it), and the import committed both rows, leaving the part with no whole on valid-time reads in between, which `verifyConstraintFences()` does not report. `reparent` cannot produce this, since it gives both halves one instant, and an imported move is now held to the same rule. Such a move is refused both-or-neither before anything is written: both rows report the new `CompositionError` code `COMPOSITION_MOVE_GAP` (`situation: "moveGap"`), whose details and message name the part, the ended window, the new attachment's window and the gap, and the part keeps its current whole. A move whose new window opens before the old one ends is still refused as `COMPOSITION_WINDOW_OVERLAP`, and a move that abuts is unchanged. Optional parts may still move across a gap. `CompositionErrorDetails` gains the `"moveGap"` member, so an exhaustive `switch` over `situation` needs a case for it.
