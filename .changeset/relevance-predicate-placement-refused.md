`.fuseWith()` on a query with a recursive traversal is now refused with `UnsupportedPredicateError` (`details.option` is `"fuseWith"`, `details.reason` is `"recursive_traversal"`) when the query is compiled. Fusion options only choose the order of hybrid matches, and a recursive statement never orders its rows by relevance, so the options used to be silently ignored: on a chain whose hybrid predicates sat on a fixed stage after a recursive one, and on a chain whose fixed first stage carried them. `having()` and `QueryBuilder.whereEdge()` / `TraversalBuilder.whereEdge()` now refuse a predicate that contains `$fulltext.matches()` or `.similarTo()` anywhere in it, with `UnsupportedPredicateError` (`details.reason` is `"having"` or `"edge_predicate"`, with `details.predicate` and `details.alias`) when they are called. A relevance predicate is applied only as a `whereNode()` match constraint on a node alias; in `having()` it used to compile to a constant-true term, so reusing a `whereNode()` match under `.not()` there returned no groups, and on its own it failed with `CompilerInvariantError`. `similarTo()` on an edge embedding field in `whereEdge()` failed the same way.
