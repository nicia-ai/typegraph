Add `bulkHardDelete(ids)` to edge collections: permanent removal of many edges of one kind as one write transaction. It leaves exactly the state that calling `hardDelete(id)` once per id inside one transaction leaves — live and soft-deleted edges are removed, absent and repeated ids are ignored, cardinality and composition claims are released, and a history store captures each removed edge's last version without recording a delete row — while resolving and judging every id before the first row is removed, so an id owned by another edge kind (`ValidationError` with `EDGE_IDENTITY_MISMATCH_CODE`) or a delete that would leave a live required composition part without its whole (`CompositionExistenceError`) refuses the call and deletes nothing. The delete is one statement per bind-budget chunk through the backend's optional `hardDeleteEdgesBatch` port, which now receives the collection's kind and must put it in the statement's `WHERE` like `deleteEdgesBatch` already does; a backend without the port falls back to one kind-asserting `hardDeleteEdge` per edge inside the same transaction. Like every batch method it fires no operation hooks, it counts one write intent per input id in transaction receipts, and it is refused on read-only views.
