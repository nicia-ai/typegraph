A write through any context over a transaction `store.transaction(fn, { accessMode: "read_only" })` opened is now refused like a write on its own `tx`. Before this, the read-only fact lived on that `tx` object, so handing `tx.sql` back to the store built a context that knew nothing of it: `store.withTransaction(tx.sql)` and `withRecordedTransaction(tx.sql, fn)` committed writes inside the "read-only" transaction on SQLite, and on PostgreSQL the engine rejected the statement and aborted the transaction. The fact now belongs to the native transaction itself, for as long as the read-only callback runs, and every context over that transaction asks it at each write. `withTransaction(tx.sql)` and `withRecordedTransaction(tx.sql, fn)` refuse every collection and identity write, `writeNodeUpsertBatch()` and `applyMergePlanInTransaction()` with the same `UnsupportedBackendCapabilityError` (capability `"write transaction access"`) and `operation` names as `tx`. A history store's `withRecordedTransaction(tx.sql, fn)` and `withEvolvedTransaction(tx.sql, plan, fn)` are refused before their callback, whatever the plan. A Store over `createPostgresTransactionBackend(tx.sql)`, or over `createSqliteBackend(tx.sql)` on a libSQL transaction, refuses its own collection and identity writes (named `store.nodes.Person.create()`), `store.clear()`, `importGraph()`, `importGraphStream()` and `trustedImportGraphStream()`, and the writes and provenance verbs in its own `store.transaction()`. Every refusal comes before any statement on SQLite and PostgreSQL alike, so the transaction stays usable. A read-only `store.transaction()` on a Store over a caller's read-write transaction runs as a savepoint, and the caller's transaction refuses writes only while that callback runs. A native read-only transaction the Store did not open carries no such fact, and the engine decides as before. One handle is still not recognized: a savepoint the caller opens with `tx.sql.transaction(...)` and adopts directly is a transaction of its own to TypeGraph on every driver but better-sqlite3, so PostgreSQL refuses the write itself and libSQL commits it.
