"@nicia-ai/typegraph": patch
---

Identity mutations (`assertSame`, `assertDifferent`, `bulkAssertSame`, `bulkAssertDifferent`, `retractSameAssertion`, `retractDifferentAssertion`, on `store.identity` and `tx.identity`) now refuse an unregistered kind, a self-assertion, or a stated window bound that is not a canonical instant before they open a transaction or take the identity graph lock. Such a call fails with the same error as before, but sooner, without issuing the lock statement and without waiting behind another writer that holds the lock. Valid calls issue the same statements, in the same order, under the same locks.

A bulk call now reads its `pairs` array once, by index, and refuses a hole or an entry that is not an object with a `TypeError` before entry. Previously a hole was skipped by `map` and reached the write: a windowed batch with a valid first pair and a hole after it wrote the first assertion before it threw, and inside `store.transaction()` a callback that caught the error committed that assertion. The `tx.identity` bulk receipt now counts the pairs the call actually processed rather than reading `pairs.length` separately.

Error precedence changes for bulk calls with more than one defect. Pairs are checked in index order and the first defect is reported; within a pair, an unregistered kind comes first, then a self-assertion, then a malformed window bound. A windowed pair with identical endpoints and a malformed `validFrom` was previously refused for the malformed bound, even in a one-pair batch, and is now refused as a self-assertion (as `assertSame` and `assertDifferent` already did); in a batch with any windowed pair, a self-assertion in an earlier pair is likewise reported ahead of a malformed bound or unregistered kind in a later one, where every pair's kinds and bounds were previously checked before any self-assertion. All of these are now reported ahead of a refusal judged against the operation's clock (a future or inverted window) in any pair.
