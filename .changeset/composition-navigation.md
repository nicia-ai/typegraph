`QueryBuilder` gains `parts()` and `wholes()`, declared-structure builder sugar over the existing recursive `Traversal` AST for a declared [composition](https://typegraph.dev/ontology#composition) relation (`partOf` / `hasPart`). Instead of naming the realizing edge kind and its direction by hand, `parts("alias", { from?, maxHops?, depth?, path? })` derives the edge kind(s) and direction(s) from the registry's composition relation and recurses to the full transitive closure by default (pass `maxHops: 1` for the direct level only); `wholes()` is the mirror, returning the ancestor chain. Direction is derived per realizing edge kind rather than fixed: a `part -> whole` edge is followed reversed and a `whole -> part` (`has_*`) edge is followed in its own direction, and a relation realized by both orientations across levels compiles to one traversal step whose direct and inverse edge-kind sets union via the existing `inverseEdgeKinds` mechanism — a mixed relation costs nothing extra to declare, and the common uniform-orientation case pays nothing extra to compile. The result alias is untyped (`DynamicNodeType`/`DynamicEdgeType`, reached via `.field(name)`), since the parts/wholes closure under a kind is registry data that may span more than one node kind with different schemas. `parts()`/`wholes()` on a kind declaring no composition parts/wholes refuses with `ConfigurationError` (`COMPOSITION_NO_PARTS_DECLARED` / `COMPOSITION_NO_WHOLES_DECLARED`) rather than returning zero rows; `expand` is not accepted on either step.

`SubgraphOptions` gains `composition?: boolean`: closes the selected root over `compositionEdgeKindsUnder` its actual kind before the existing projection runs, in addition to whatever `edges` already lists — the whole-plus-parts export unit. This is set-level: a root kind declaring no composition parts contributes nothing and the read still runs; a graph declaring no composition relation at all refuses with `ConfigurationError` (`COMPOSITION_NO_PARTS_DECLARED`). Because which composition edge kinds join depends on the root's runtime kind, `composition: true` widens the result's edge-key type to the graph's whole edge-kind union (the new `SubgraphResultEdgeKinds`), so every key the traversal can put in `adjacency` / `reverseAdjacency` is reachable through the result type; `composition` absent or `false` keeps the existing `edges`-list typing unchanged.

`TraversalBuilder` gains `toKindSet(kinds, alias)`, a general-purpose finalizer (parallel to `to()`/`toDynamic()`) for an explicit, already-resolved set of target node kinds rather than one compile-time-known or runtime-resolved kind — what `parts()`/`wholes()` need and any future caller with the same shape of problem can reuse.

### Fixes

A recursive traversal combining `.recursive()` with a non-empty inverse edge-kind set (`{ expand: "inverse" }`, or the mixed-orientation case `parts()`/`wholes()` now exercise) compiled its recursive term as two branches, each independently self-joining the recursive CTE, unioned with `UNION ALL`. PostgreSQL refuses this — a recursive CTE's self-reference may appear at most once in its recursive term, even split across `UNION ALL` arms — while SQLite's looser recursive-CTE implementation accepted it, so the defect was invisible until run against a real PostgreSQL engine. Both edge orientations are now normalized into one relation, computed once before recursion starts, so the recursive term joins the recursive CTE exactly once on every dialect.
