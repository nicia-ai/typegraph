**A stored schema document no longer diffs as a breaking change just because the JSON Schema projection spells it differently.** Zod's projection changed how it writes two constructs: a union of bare primitives (`anyOf: [{ type: "string" }, { type: "null" }]`, now `type: ["string", "null"]`) and a closed tuple's arity (a bare `prefixItems`, now `items: false` with `minItems`/`maxItems` restated). A graph whose document was stored under the earlier spelling reported every `.nullable()`, primitive `z.union()` and `z.tuple()` property as "Property schemas changed incompatibly", so `createStoreWithSchema()` refused to open it without a `migrateSchema()` and `createVerifiedStore()` / `requiresMigration()` reported a migration that was not needed. The schema diff now folds both spellings before comparing, including a union nested in a union (`z.union([...]).nullable()`, `.nullable().nullable()`) — on every path built on `computeSchemaDiff()` — and `isStructuralSubtype()` reads the two tuple spellings as the same tuple, as it already did for the two union spellings. The fold rewrites only the keywords that spell these constructs: a union member carrying any other keyword, instance data (`default`, `const`, `examples`) and unknown extension keys are compared exactly as before, so a genuine change is still reported. Two stored shapes still read as changed, because the document cannot say what was meant. A tuple with an optional trailing member (`z.tuple([a, b.optional()])`): the earlier projection wrote it identically to the required tuple, so a bare `prefixItems` is read as the required-arity tuple. And a tuple with a rest element (`z.tuple([a], rest)`): the earlier projection wrote it with no `minItems`, which is exactly how the current one writes `z.tuple([a.optional()], rest)`, so it is read as written. Beside an explicit `items`, `minItems` is always compared as stated — the current projection omits it when every prefix member is optional, so required and all-optional tuples are different schemas to both the diff and `isStructuralSubtype()`. Run `migrateSchema()` once to restamp a document holding either shape. Schema hashes are unchanged.

### Breaking

- `JsonSchema`, the projected schema type the `/schema` entrypoint exports, widens `items` from `JsonSchema` to `JsonSchema | boolean` and gains `prefixItems`, `minItems` and `maxItems`, because a closed tuple now projects as `items: false`. Code that reads `.items` as a schema narrows out the boolean first.
