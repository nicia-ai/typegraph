**A stored schema document no longer diffs as a breaking change just because the JSON Schema projection spells it differently.** Zod's projection changed how it writes two constructs: a union of bare primitives (`anyOf: [{ type: "string" }, { type: "null" }]`, now `type: ["string", "null"]`) and a tuple's arity (a bare `prefixItems`, now `items: false` with `minItems`/`maxItems` restated). A graph whose document was stored under the earlier spelling reported every `.nullable()`, primitive `z.union()` and `z.tuple()` property as "Property schemas changed incompatibly", so `createStoreWithSchema()` refused to open it without a `migrateSchema()` and `createVerifiedStore()` / `requiresMigration()` reported a migration that was not needed. The schema diff now folds both spellings before comparing — on every path built on `computeSchemaDiff()` — and `isStructuralSubtype()` reads the two tuple spellings as the same tuple, as it already did for the two union spellings. The fold rewrites only the keywords that spell these constructs: a union member carrying any other keyword, a tuple whose `minItems` is below its prefix length (an optional trailing member), instance data (`default`, `const`, `examples`) and unknown extension keys are compared exactly as before, so a genuine change is still reported. Schema hashes are unchanged.
