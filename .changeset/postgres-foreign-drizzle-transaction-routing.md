`createPostgresBackend(tx)` now treats a transaction object from another loaded copy of `drizzle-orm` as a transaction. When an application and TypeGraph each resolved their own copy of `drizzle-orm`, `instanceof PgTransaction` failed for such a handle, so `createPostgresBackend` built a root backend over the caller's transaction instead of the transaction-scoped one. Its `transaction()` then opened a savepoint that claimed to report the commit outcome, overwrote the enclosing transaction's outcome marker, and the enclosing `transaction()` call failed with `TransactionOutcomeUnknownError`. The same check decided whether lazy DDL and schema-write DDL checked the caller's session schema instead of pinning its `search_path`, whether recorded-anchor retention adoption ran in a savepoint, and whether a vector search's `SET LOCAL` overrides were restored after the search. Every such check in the PostgreSQL adapter now uses Drizzle's brand check, which adoption already used, so a transaction from either copy takes the transaction-scoped path. `buildPostgresEngineProfile` likewise refuses such a handle with `TRANSACTION_REQUIRES_SCOPED_BACKEND`, as it already refused its own copy's.
