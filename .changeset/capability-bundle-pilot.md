`DeleteLegacyRecordedAnchorMapOptions.backend` now statically requires `executeStatement` (its type is `Pick<GraphBackend, "dialect" | "execute" | "tableNames" | "transaction"> & Required<Pick<GraphBackend, "executeStatement">>`), and the runtime guard that used to refuse a `backend` object missing it at call time is deleted. The only callers this affects are the ones that would have gotten that runtime refusal today; converting a runtime refusal into a compile error is the honest-tightening class this library has shipped before, so this ships as a minor rather than a patch.

Six capability bundles ship as the pilot of a larger consolidation: `claims` (gated, core `claimEdgeCardinality`/`claimEdgeCardinalityBatch`/`purgeEdgeClaims`/`hardDeleteUniquesByConcreteKind`, the one bidirectional cross-check against `constraintClaims`, refusing `CONSTRAINT_CLAIM_SURFACE_MISMATCH` on disagreement in either direction); `statementExecution` (gated, core `executeStatement`, refusing `IDENTITY_REQUIRES_STATEMENT_EXECUTION` when the core is absent); `recordedRevisionOrigins` (gated, core `ensureRevisionOriginsTable`, refusing with the operation's own typed error); `batchPointRead` (graduated, `getNodes` falls back to per-id `getNode`, `getEdges` falls back to per-id `getEdge`); `uniqueSidecarBatch` (graduated, `insertUniqueBatch` falls back to `issueClaimsIndividually`, `checkUniqueBatch` falls back to a per-key loop, `hardDeleteUniquesByNodeIds` refuses with the operation's own typed error); `contributionHealth` (graduated, `verifyContributions`/`repairContributions`/`rebuildContribution` each refuse with the operation's own typed error, `probeContributions` falls back to `{ entries: [] }`).

Each bundle has one verdict resolver and one member accessor, so a caller never re-derives "does this backend support X" from a scattered `undefined` check. `CAPABILITY_BUNDLES` (and the six named bundle constants, `resolveBundle`, `bindCore`, `bindExtra`, `bindExtraIfReachable`, and the verdict/binding types) are exported because the forthcoming conformance kit generates its refusal-conformance rows directly from the registry, so a bundle landing later grows the kit's coverage with no kit change.

Every bundle's member accessor applies the same disposition-keyed port-mismatch rule: a `refuse`-disposition row whose backend object cannot actually reach the member throws that bundle's own `portSurfaceCode`; a `fallback`-disposition row whose port cannot reach the member takes its declared fallback instead of throwing, because a fallback row is defined to degrade rather than assert.

This bundle model covers six of the twenty-one member-bearing operation families measured across the codebase; the remaining fifteen are a named follow-up workstream, not a silent gap — their members keep working exactly as before, unbundled. No shipped configuration changes behavior: both bundled backends already carry every member each pilot bundle needs.
