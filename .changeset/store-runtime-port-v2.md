The Store's internal runtime port now advertises version 2. Functions in one copy of the library reach a Store built by another copy in the same process through that port, for example `importGraph`, `importGraphStream` and `exportGraphStream`. This release changes how the port's members are called: they take the caller's operation, not its transaction. Before this change a copy of an earlier release still found the port under the old version. On a graph without identity the call happened to work. On a graph that declares identity it failed with an unrelated property error (`Cannot read properties of undefined`). Now a copy finds the port only on a Store built by a copy of the same port version. Otherwise it refuses with the incompatible-version `TypeError`, "Cannot access this Store's runtime port. The Store may come from an incompatible TypeGraph version.", before it runs any statement. `importGraph` and `importGraphStream` report that refusal as their existing `ConfigurationError` ("Interchange import received an unrecognized ingestion target"), with the `TypeError` as its `cause`. Two copies of the same release, such as its ES module and CommonJS builds, still share the port. The transaction runtime port's call shape did not change, so it keeps its version.

### Upgrade notes

- **Load one TypeGraph version per process.** A Store built by this release and a copy of an earlier release in the same process (or the reverse) now refuse each other before any statement. Before, a call between them worked or failed with an unrelated error, depending on whether the graph declares identity. This applies to the interchange functions and every other function that takes a Store. If you see "Cannot access this Store's runtime port", check `npm ls @nicia-ai/typegraph` or `pnpm why @nicia-ai/typegraph` for a second version, usually a dependency that pins its own. Align the version ranges, or deduplicate with `overrides` (npm), `pnpm.overrides` or `resolutions` (Yarn). Data does not need migrating: the stored schema does not change.
