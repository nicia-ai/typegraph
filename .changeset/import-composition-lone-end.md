`importGraph` and `importGraphStream` with `onConflict: "update"` no longer write the end of a composition attachment alone when the document attaches the part again with a row that is not applied. 0.75 refused such an end only when the document held exactly one row ending the attachment and exactly one re-attaching row refused while the document was classified. Other shapes still committed the end and left an optional part with no whole: a re-attaching row whose caller-assigned id names a stored edge (an ended edge of the same part, a deleted edge, which import skips without an error, or another part's edge), two refused re-attaching rows, a refused row whose id the document repeats, a repeated end, a row ending an attachment the same document creates while the row moving the part on is refused when it is created, or a repeat ending an attachment that an earlier repeat of the same id created after the id's first row was refused.

Every part a row can stop attaching, outside a pair applied as one move, that another row attaches again is now judged once by one verdict, whatever stage refuses its re-attaching rows. The verdict is taken from the writes the rows applied, not from what the document planned: a row ends the attachment only when its write was applied as an update over an open window attaching the part, so a refused row, or a repeat that creates ended history under the id of a refused attachment, ends nothing, and a refused end does not stop the replacement it would have ended from counting as the part's new attachment. When an end was applied and none of the rows meant to attach the part again attaches it, the end applied last is refused with `INTERCHANGE_COMPOSITION_MOVE_INCOMPLETE`, naming those rows, and the edge writes run again, so the part keeps the last whole a row of the document actually gave it. When every row that can end the attachment ends the stored edge attaching the part, and no other re-attaching row can be applied, the classification already settles the refusal, and those ends are refused before anything is written. Any other refusal rolls the edge writes back to a savepoint and runs them again with the end refused, as a failed move already does; a backend whose transaction offers no savepoint aborts such an import with `IMPORT_COMPOSITION_MOVE_REQUIRES_SAVEPOINT` instead of committing the lone end. A row restating the edge being ended, or a row whose window is already ended, does not count as attaching the part again, so a lone end the document states on purpose is still written. Required parts were already protected by `COMPOSITION_DETACH_REFUSED`; when the refusal is settled before anything is written, their end now reports `INTERCHANGE_COMPOSITION_MOVE_INCOMPLETE` like an optional part's. The outcome is the same at every `batchSize` and through `importGraphStream` for a document in one chunk.
