`weightedShortestPath` refuses a `weightProperty` that a JSON path cannot address as a top-level object key on every backend: an all-digit name such as `"0"`, the name `"-"`, and a name containing a double quote. All three now throw `ConfigurationError` naming the property and the reason before any statement runs, identically on SQLite and PostgreSQL. An all-digit name used to be read as an array index of the edge's properties on SQLite, so every weight was reported missing or silently replaced by `defaultWeight`, while PostgreSQL read the object key; `"-"` threw a plain `Error` about JSON Pointer syntax; and a name containing a double quote was not found by libSQL's JSON path (SQLite 3.45), where it was likewise reported missing or defaulted. Names containing `/`, `~`, single quotes, backslashes, dots, brackets or spaces are unaffected and read the same key on both backends. On SQLite, `DialectAdapter.jsonExtractDouble` now casts its result to `REAL`, so an integer-valued JSON number is a double there as the member's contract says, and a `defaultWeight` is bound as a double on both backends.
