**The structural `subClassOf` / `equivalentTo` check now accepts a finite value set under a bounded parent.** A child pinned with `z.literal` or `z.enum` is judged value by value against the parent's length bounds, `regex()` pattern (and the patterns behind `startsWith()`, `endsWith()`, `includes()`, `lowercase()` and `uppercase()`), numeric bounds, `multipleOf()` and type, so `z.literal("x")` under `z.string().min(1)`, `z.enum(["a", "b"])` under `z.string().max(10)` and `z.literal(5)` under `z.int().min(0)` no longer fail registry build with `ONTOLOGY_SUBCLASS_NOT_STRUCTURAL_SUBTYPE`. A value is accepted only when both Zod and JSON Schema accept it: lengths are counted in code points and in UTF-16 units, patterns are tested with and without the `u` flag, and `multipleOf` is decided on exact decimals. Standard formats such as `z.email()` are still not judged by value. A record's key set now compares as a subtype instead of requiring identical `propertyNames`, so `z.record(z.enum(["a", "b"]), V)` extends `z.record(z.string(), V)`. A finite value set is judged only when every pinned value is a value of the child's own type and the set is not empty, so no keyword is ever satisfied vacuously.

The live check also stays conservative around three constraints the JSON Schema projection drops, which let it accept pairs whose child admits a value the parent refuses; each is now refused as incomparable. A string format a later format replaces: `z.url().startsWith("https://")` projects only its `starts_with` format, so `z.string().startsWith("https://")` passed beneath it. An overwrite (`.trim()`, `.toLowerCase()`, `.toUpperCase()`, `.normalize()`, `.overwrite()`): on a parent, when another check runs after it and judges the transformed value (`z.string().min(2)` passed under `z.string().trim().min(2)`); on either side, when it runs after another check, so the node stores a value that check never saw. A `z.literal(NaN)` or `z.literal(±Infinity)`, which projects as `null` (`z.literal(NaN)` passed under `z.number()`). A replaced format, or an overwrite that runs only ahead of the other checks, is refused on the parent side alone; in every case a schema both sides share still compares equal. A record whose key schemas are two different `$ref` definitions reports `incomparable` (`schema-reference`) instead of `not-subtype` (`property-names-mismatch`), the same as every other unresolved reference pair.
