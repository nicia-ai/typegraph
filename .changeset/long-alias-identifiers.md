Query aliases of up to 63 characters now work on PostgreSQL. The compiler derives SQL identifiers from an alias (`<alias>_id`, `<alias>_valid_from`, `cte_<alias>`, `<alias>_<field>` projections, recursive `<alias>_depth` / `<alias>_path` columns), and PostgreSQL clips identifiers to 63 bytes, so names that differed only past byte 63 became one identifier: a whole-node select failed from a 59- or 60-character alias, a root-id read from 61, and a field projected under a long alias, or under a multi-byte field name, could come back missing or wrong. SQLite ran the same queries correctly.

Every derived name, including the `lm_<alias>` table aliases of late-materialized `orderBy().limit()` queries, is now identified by the parts it is built from (an alias and a column, or an alias and its role), never by the text they concatenate to, and is written into the statement as its own SQL fragment node rather than as text. Each SQL statement then allocates physical names once, on every backend: a name that fits in 63 bytes keeps its spelling unless an earlier name in the statement already holds it, and every other name takes its leading bytes plus a 64-bit hash, chosen so that no other generated name or quoted identifier in the statement holds it. Names are compared ASCII case-insensitively, the way both SQLite and PostgreSQL compare them. The same query always compiles to the same SQL, and SQL whose names all fit and differ is unchanged.

This also fixes collisions that did not need a long alias. A part's `edge_id` property and the `id` of the `<alias>_edge` alias `parts()` derives both read as `<alias>_edge_id`, and both selections returned the edge id. An edge aliased `e` and a node aliased `e_from` or `e_to` shared `e_from_id` / `e_to_id`, returning the wrong ids on SQLite and an ambiguous-column error on PostgreSQL. Two aliases differing only in case, such as `item` and `Item`, produced one CTE name that both engines rejected. Field names, JSON paths, string literals, and output keys pass through unchanged whatever characters they contain.

Result decoding, `store.batchOnce()` (including recursive reads with default `<alias>_depth` / `<alias>_path` outputs on SQLite), checked reads, set operations, cursor pages, `compareAndSet()`, `updateWhere({ candidates })`, and search candidates read the allocated names, and `toNodeCandidateSelection().idColumn` names the column `compileNodeCandidateIds()` emits. The default `<alias>_depth` / `<alias>_path` outputs of `recursive({ depth: true, path: true })` and the `<alias>_edge` alias of `parts()` / `wholes()` are no longer refused when the derived name exceeds 63 characters. In the exported query AST, a whole-node projection's `outputName` and a selective field's `outputName` are now structured generated names, and `SqlIdentifierChunk` gains an optional `deferred` member that compiled statements never carry.
