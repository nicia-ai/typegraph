The public custom `metaEdge()` factory, the public `InferenceType` union, and the deprecated `sameAs`/`differentFrom` type-level factories are removed. None of them ever drove runtime behavior beyond serialized introspection metadata: every closure and write-path decision for a meta-edge is made per literal name, never read off a `MetaEdge`'s properties. Free-form, type-level vocabulary the library has no built-in reasoning for now belongs in `defineGraph({ annotations })` — see [Type-Level Annotations](https://typegraph.dev/ontology#type-level-annotations) and `examples/08-custom-ontology.ts` for a complete example. Replace `sameAs(A, B)` with `equivalentTo(A, B)` (behaviorally identical in every release `sameAs` shipped in); delete `differentFrom(A, B)` calls (it was decorative and never enforced) or, for real cross-kind instance identity, use the TypeGraph Identity Profile (`identity: { sameIdAcrossKinds: "fold" }` and `store.identity`). The serialized schema document drops `metaEdges[*].transitive`/`symmetric`/`reflexive`/`inverse`/`inference` on the next write that a real ontology change triggers — `SerializedMetaEdge` now carries only `name`/`description` — and the deserializer's Zod validator no longer requires these fields, so a document written before this release keeps loading and its extra fields are ignored. Upgrading the library alone does not rewrite a stored document: `ensureSchema` only writes a new version when it detects a semantic change, so a graph whose ontology is otherwise untouched keeps its pre-removal document (and pays the slower parse-and-diff path on every boot, instead of the schema-hash fast path) until its next real schema change lands. A persisted `sameAs` relation keeps folding into the equivalence closure exactly like `equivalentTo`; a persisted `differentFrom` relation keeps being inert. A relation naming a custom `metaEdge()` you called before this release is different: since the factory that declared it is gone, your upgraded graph can no longer serialize that relation at all, so the first commit `ensureSchema` makes after upgrading auto-migrates it away — classified `safe` (a custom name reaches no closure or write-path decision) and dropped from the rewritten document with no opt-in. Copy anything you need from that relation into `annotations` **before** upgrading; see the migration guide linked below. The `OntologyChange` union's `entity` field narrows from `"metaEdge" | "relation"` to `"relation"`: a meta-edge name leaving the serialized `metaEdges` catalog is always a consequence of its last relation being removed or added, never an independent event. Graph extensions continue to refuse a `metaEdge` name outside the closed core set — nothing in this change reopens that.

**Rolling deploys and rollback.** The new serializer output is a one-way door: a document written by a `@nicia-ai/typegraph` release with this change (only after that document's next real schema commit — see above) cannot be parsed by an earlier release, because the pre-change `serializedSchemaZod` required `transitive`/`symmetric`/`reflexive`/`inference` on every `ontology.metaEdges` entry. Upgrade every reader of a shared database (every application instance, in a mixed-version fleet) to this release or later before any of them commits a schema change, and do not roll back to a pre-change release once one has — an older instance's `parseSerializedSchema` throws on the rewritten document instead of degrading.

See [Upgrading past the removed `sameAs`/`differentFrom`/`metaEdge()` APIs](https://typegraph.dev/schema-evolution#upgrading-past-the-removed-sameasdifferentfrommetaedge-apis) for the complete migration guide.

### Breaking

- Removed: `metaEdge()` and `MetaEdgeOptions` (`@nicia-ai/typegraph`, `@nicia-ai/typegraph/core`).
- Removed: the public `InferenceType` union (`@nicia-ai/typegraph`, `@nicia-ai/typegraph/backend`).
- Removed: `MetaEdgeProperties.transitive`, `.symmetric`, `.reflexive`, `.inverse`, and `.inference` — `MetaEdgeProperties` now carries only `description`.
- Removed: the deprecated `sameAs()` and `differentFrom()` relation factories (`@nicia-ai/typegraph`), and the matching `core.sameAs` / `core.differentFrom` members of the exported `core` object. The `sameAs`/`differentFrom` meta-edge NAMES are still recognized when they appear in a persisted document or a declarative graph extension — only the factory functions that construct them from code, and the `core.sameAsMetaEdge` / `core.differentFromMetaEdge` objects, are gone; `core` no longer carries any way to construct a relation naming either.
- Changed: `SerializedMetaEdge` narrows to `{ name, description }`, dropping `transitive`/`symmetric`/`reflexive`/`inverse`/`inference`. This document shape is a one-way door — see "Rolling deploys and rollback" above.
- Changed: `OntologyChange["entity"]` narrows from `"metaEdge" | "relation"` to `"relation"`. Code that matched on `entity === "metaEdge"` no longer has a case to match; the relation-level severity table classifies these changes.
