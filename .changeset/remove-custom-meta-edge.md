The public custom `metaEdge()` factory, the public `InferenceType` union, and the deprecated `sameAs`/`differentFrom` type-level factories are removed. None of them ever drove runtime behavior beyond serialized introspection metadata: every closure and write-path decision for a meta-edge is hardcoded per literal name in `collectOntologyRelations` (`src/registry/kind-registry.ts`) and `classifyKnownRelationSeverity` (`src/schema/ontology-change.ts`), never read off a `MetaEdge`'s properties. Free-form, type-level vocabulary the library has no built-in reasoning for now belongs in `defineGraph({ annotations })` — see [Type-Level Annotations](https://typegraph.dev/ontology#type-level-annotations) and `examples/08-custom-ontology.ts` for a complete example. Replace `sameAs(A, B)` with `equivalentTo(A, B)` (behaviorally identical in every release `sameAs` shipped in); delete `differentFrom(A, B)` calls (it was decorative and never enforced) or, for real cross-kind instance identity, use the TypeGraph Identity Profile (`identity: { sameIdAcrossKinds: "fold" }` and `store.identity`). The serialized schema document drops `metaEdges[*].transitive`/`symmetric`/`reflexive`/`inverse`/`inference` on the next write — `SerializedMetaEdge` now carries only `name`/`description` — and the deserializer's Zod validator no longer requires these fields, so a document written before this release keeps loading and its extra fields are ignored. A persisted `sameAs` relation keeps folding into the equivalence closure exactly like `equivalentTo`; a persisted `differentFrom` relation keeps being inert. The `OntologyChange` union's `entity` field narrows from `"metaEdge" | "relation"` to `"relation"`: the removed `"metaEdge"` arm was a second, contradicting classifier for a state the relation-level diff already classified correctly (a meta-edge name leaving the serialized `metaEdges` catalog is always a consequence of its last relation being removed or added, never an independent event, since the catalog is derived 1:1 from `relations`). Graph extensions continue to refuse a `metaEdge` name outside the closed core set — nothing in this change reopens that.

See [Upgrading past the removed `sameAs`/`differentFrom`/`metaEdge()` APIs](https://typegraph.dev/schema-evolution#upgrading-past-the-removed-sameasdifferentfrommetaedge-apis) for the complete migration guide.

### Breaking changes

- Removed: `metaEdge()` and `MetaEdgeOptions` (`@nicia-ai/typegraph`, `@nicia-ai/typegraph/adapters/drizzle/*`).
- Removed: the public `InferenceType` union (`@nicia-ai/typegraph`, `@nicia-ai/typegraph/backend`, `@nicia-ai/typegraph/schema`).
- Removed: `MetaEdgeProperties.transitive`, `.symmetric`, `.reflexive`, `.inverse`, and `.inference` — `MetaEdgeProperties` now carries only `description`.
- Removed: the deprecated `sameAs()` and `differentFrom()` relation factories (`@nicia-ai/typegraph`). The `sameAs`/`differentFrom` meta-edge NAMES are still recognized when they appear in a persisted document or a declarative graph extension — only the factory functions that construct them from code are gone.
- Changed: `SerializedMetaEdge` narrows to `{ name, description }`, dropping `transitive`/`symmetric`/`reflexive`/`inverse`/`inference`.
- Changed: `OntologyChange["entity"]` narrows from `"metaEdge" | "relation"` to `"relation"`. Code that matched on `entity === "metaEdge"` no longer has a case to match — that classification arm was removed as a redundant, contradicting second owner of a decision the relation-level severity table already made correctly.
