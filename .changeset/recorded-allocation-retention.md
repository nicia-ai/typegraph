Add `store.pruneRecordedInstants(before, { limit })` for bounded recorded allocation-log retention. Each call deletes one limited revision range and returns the deleted count, retained boundary, and whether more physical cleanup remains. A durable coverage watermark distinguishes explicitly pruned lookup coverage from unlogged history and valid naturally gapped logs. Saved anchors, allocation ownership, and captured entity history remain intact.

Upgrade storage to base-schema version 9 before calling `resolveRecordedInstant` or enabling pruning. A missing retention column raises `BaseSchemaMigrationError` (including `details.missingColumn`), rather than a raw driver error; its installed version is unknown until the deployment marker is checked. This release adds the nullable `anchor_retention` column to the recorded clock; bundled adapters adopt it automatically during privileged open. PostgreSQL skips clock DDL when the column is already installed; an upgrade that conflicts with active captured writes fails immediately with a lock-not-available error so operators can retry after those transactions finish. DML-only deployments must apply the published base-schema migration first. Custom schema providers must include the column and implement the version 9 adoption step. Upgrade every reader sharing the database before starting a retention job, and coordinate cleanup with checkpoint, replication, and entity-history retention requirements. Pruning retries whole transactions after serialization conflicts and tolerates healthy clock advances that do not invalidate its retained boundary. Lookup preserves its validation-first ordering and `resolve-recorded-anchor` missing-storage surface label. The first batch retires lookup coverage below its boundary immediately; resume batches while `hasMore` is true to finish deleting already retired rows.
