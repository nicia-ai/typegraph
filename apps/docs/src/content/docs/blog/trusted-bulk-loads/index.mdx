`importGraph` validates every row it writes: schema shape, edge endpoint
existence, cardinality, conflict handling. That's the right default;
almost every import is from a source you don't fully trust yet. But
there's one case where every one of those checks is pure overhead: loading
a fresh, dedicated database from data your own export already validated.
0.37 adds `trustedImportGraph` / `trustedImportGraphStream` for exactly
that case, a distinct, deliberately narrow path that trusts the producer
instead of re-checking it.

## Measured: 200,000 nodes, 200,000 edges, three runs

Same interchange data, same fresh in-memory SQLite database, loaded two
ways:

```typescript
const resultA = await importGraph(storeA, data, {
  onConflict: "error",
  batchSize: 5000,
});

const resultB = await trustedImportGraphStream(storeB, chunksOf(data));
```

```text
run 1 — importGraph: 6783ms   trustedImportGraphStream: 2455ms
run 2 — importGraph: 7253ms   trustedImportGraphStream: 2206ms
run 3 — importGraph: 5048ms   trustedImportGraphStream: 2116ms
```

Consistently 2.5-3x faster across all three runs, on 200,000 nodes and
200,000 edges into a fresh database. The gap is exactly the work the
trusted path skips: no per-row schema re-validation, no edge-endpoint
existence checks, no cardinality enforcement, no conflict-resolution
branching. What remains is engine-native inserts straight into the
tables, deferred secondary-index builds, and one transaction start to
finish.

## What "trusted" actually means

`trustedImportGraph` bypasses the normal store write pipeline entirely,
rather than flipping validation off inside `importGraph`, and the contract
is deliberately narrow:

- The TypeGraph node and edge tables must be **globally empty**. A
  different graph already living in the same database also counts as
  non-empty.
- The caller guarantees property shapes, endpoint existence, edge endpoint
  types, cardinality, and duplicate-free IDs. Only stream ordering and
  known kind names are checked.
- Recorded-time history, revision tracking, node uniqueness constraints,
  `searchable()` fields, and `embedding()` fields are rejected in this
  first version; their sidecar writes would otherwise be silently
  skipped.
- Nodes must precede edges in the stream. The complete stream is one
  transaction: data insertion, temporary secondary-index removal, index
  rebuilding, and planner-statistics refresh either all commit or all
  roll back.

Try to load into a database that already has rows, and it fails loudly
rather than silently corrupting or duplicating anything:

```text
TrustedImportError: Trusted import requires globally empty TypeGraph node and edge tables.
  details: { tables: ["typegraph_nodes", "typegraph_edges"], reason: "database_not_empty" }
```

## The streaming shape

`trustedImportGraphStream` takes an async iterable of
`GraphInterchangeChunk` (a header, then node chunks, then edge chunks, in
that order):

```typescript
async function* chunksOf(
  data: GraphData,
): AsyncIterable<GraphInterchangeChunk> {
  const { formatVersion, exportedAt, source } = data;
  yield { type: "header", header: { formatVersion, exportedAt, source } };
  for (let i = 0; i < data.nodes.length; i += 5000) {
    yield { type: "nodes", nodes: data.nodes.slice(i, i + 5000) };
  }
  for (let i = 0; i < data.edges.length; i += 5000) {
    yield { type: "edges", edges: data.edges.slice(i, i + 5000) };
  }
}

const result = await trustedImportGraphStream(store, chunksOf(data));
// { nodes: 200000, edges: 200000 }
```

Streaming rather than a single in-memory `GraphData` array matters at real
scale: the LDBC SNB bulk-load benchmark behind [the LadybugDB
comparison](/blog/benchmarking-typegraph-neo4j-ladybugdb) reads the source
CSVs in two bounded passes (nodes, then edges) through exactly this
streaming path, rather than holding a multi-million-row graph in memory to
satisfy the nodes-before-edges ordering requirement.

## When to reach for which

| You have...                                                             | Use                                               |
| ----------------------------------------------------------------------- | ------------------------------------------------- |
| External or uncertain data, need conflict handling                      | `importGraph` / `importGraphStream`               |
| A graph that needs history, uniqueness, searchable, or embedding fields | `importGraph` / `importGraphStream`               |
| Trusted data, but the database isn't a fresh dedicated target           | Collection `bulkInsert`                           |
| Trusted data, loading a fresh dedicated database, once                  | `trustedImportGraph` / `trustedImportGraphStream` |

Supported native paths are synchronous prepared-statement SQLite
(`better-sqlite3`, Bun SQLite) and transaction-capable PostgreSQL adapters
with raw execution support. Remote libSQL/Turso, Cloudflare D1, and
HTTP-only PostgreSQL adapters reject the call outright with
`TrustedImportError` (`details.reason === "backend_unsupported"`) rather
than silently falling back to a slower path.
