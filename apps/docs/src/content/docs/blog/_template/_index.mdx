# UPDATE NOTES. A published post is a record of its time: never rewrite its
# prose, numbers or dates. When a later release makes a statement untrue in a

#   </UpdateNote>

# - Where: immediately after the paragraph or code block it corrects, so the
#   correction sits with the claim.
# - What it says, in one to three sentences: what changed, since which
#   version, and what to use now, with a link to the current docs page (check
#   that the page and anchor exist).
# - What it must not do: edit the original text, change its numbers or dates,
#   or editorialize. It is a correction, not a retrospective.
# - Props: `date` (ISO date of the update, required) and `version` (the
#   release it refers to, optional). The body is Markdown. Keep a blank line
#   after the opening tag and before the closing tag so the body is parsed as
#   Markdown.
# - Not for style, polish, or changes that do not affect what a reader would
#   do; those leave the post as it is.
